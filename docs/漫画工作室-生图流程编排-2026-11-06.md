# 漫画工作室 · 生图流程编排方案 · 2026-11-06

> 用户需求：在 **AI-Anime** 新增「漫画工作室」页面，用素材库里的一个固定角色，生成一套剧情能完整衔接的漫画；保留**真人漫画 / 动漫漫画**两种风格；先测真人风格；成品效果参考 `桌面\douyin_video\小禾-路线C。`；**AI-Anime 负责制作底图，`D:\剪辑应用` 负责完善剧情与排版**。
>
> **本轮只做调研与流程编排，未改任何功能代码。** 开工需用户确认 §11 的决策项。

## 0. 一句话结论

**AI-Anime = 底图工厂**（分格脚本 → 角色一致 → 动作页生成 → 导出漫画包）；**`D:\剪辑应用` = 剧情与排版层**（`/comic` 页加旁白框、气泡、A/B/C 分支、批量出格）。

三条来自实测、决定架构的硬约束：

| # | 结论 | 出处 |
|---|---|---|
| 1 | **文字绝不交给生图模型**。Agnes 一次渲染十几处中文必崩（大字号勉强、小字乱码），且与喂不喂参考图无关 | `D:\剪辑应用\CHECKPOINT-2026-11-05.md` P21 起因、ROADMAP P21 |
| 2 | **跨格同脸主要靠「复用同一张底图」，不靠模型保持身份**。参考作 16 格里第 10–13 格姿势/衣褶/辫位完全一致只换表情与气泡，第 15/16 格同底图换气泡 → **16 格实际只需 8~10 张生成图** | 同上，逐格比对 |
| 3 | **Agnes 没有 seed 参数**，不能靠随机种子锁一致性；只能靠固定参考图 + 固定文本块 + 复用底图 | 本项目 `ai-service.util.ts` 请求体、官方三模型文档 |

另有一条今天踩过的坑：**图生图提示词不能写「镜头先拍…再展示…最后回切…」**，模型会一字不差做成三格拼图；也不能用 `style` 参数（`realistic`/`anime` 会注入画风前缀污染参考图）。见 `docs\图生图-提示词指南.md`。

## 2. 两项目分工与对接契约

```
AI-Anime（漫画工作室）                    D:\剪辑应用（/comic 排版页）
  分格脚本 / 角色卡 / 底图生成      ──▶    导入漫画包 → 套文字层 → 逐格微调 → 出成品格
  （不渲染任何中文）                        （不调用任何生图模型）
```

**AI-Anime 导出「漫画包」`comic-<id>.zip`（一期交付物）**：

```
comic-<id>.zip
├─ 格01.png … 格16.png        # 1024×1536 底图；复用格是同一张图的副本
├─ panel-spec.json            # 对齐剪辑应用现有单格结构的「数组版」
└─ manifest.json              # 角色/风格/模型/比例/页数/底图数/积分/生成时间

    {
      "page_no": 1, "base_image": "格01.png", "reuse_group": "G1",
      "scene_id": "S1", "continuity": "故事开场",
      "w": 1024, "h": 1536, "view": { "fit": "cover", "zoom": 1, "offX": 0, "offY": 0 },

      "bubs": [ { "text": "太好了……我就知道，你一定会有出息的！", "x": 0.55, "y": 0.08 } ],
      "ch": null

    {
      "page_no": 2, "base_image": "格02.png", "reuse_group": "G2",
      "ch": { "guide": "你会怎么选？", "options": ["A …", "B …", "C …"], "highlight": 2 },
      "nar": { "on": false }, "bubs": []

```

**双方边界（写死，避免互相越界）**：

- AI-Anime **不**渲染中文、不画气泡、不做分格拼图、不生成 A/B/C 选项卡画面

- 剪辑应用 P21 已明确「本页不调用任何生图模型」「`panel-spec.json` 剧本格式已预留，可喂将来的批量渲染」→ 批量导入是**该项目二期**的改动，需用户决定是否本轮一起做

## 3. 数据模型（新增，不动现有表）

### 3.1 `comic_projects`

| 字段 | 说明 |
|---|---|
| `id` / `user_id` / `title` | 基础 |
| `style_mode` | `live_action`（真人，默认先测） / `anime`（动漫） |
| `character_id` | 固定角色（`characters` 表） |
| `character_card` | **角色卡全文**（JSON/Text，一次写定全片复用） |
| `costume_card` | **服装卡全文**（逐件，跨格最易漂移） |
| `character_ref` / `costume_ref` | 参考图 URL（按 style_mode 从角色双风格字段取） |
| `style_block` | 画风文本块（真人/动漫各一套） |
| `ratio` / `image_size` / `model` | `2:3` / `1K`~`4K` / `agnes-image-2.5-flash`（默认）或 2.1 |
| `panel_spec` | 完整分格脚本 JSON（唯一真相源） |
| `status` | `draft` → `script_review` → `generating` → `completed` |
| `export_url` | 漫画包 ZIP |

### 3.2 `panel_spec.panels[]`（每格字段）

| 字段 | 作用 |
|---|---|
| `page_no` / `scene_id` | 页序、场景锚点 |
| `continuity` | **承接上一格的一句话**（剧情连贯的关键，不重复描述场景） |
| `reuse_group` | **底图复用组**；同组只生成 1 张底图，其余格复制 |
| `base_image_id` / `output_url` | 复用指向 / 成图 |
| `action` / `expression` / `camera` | 本格唯一变量：动作、表情、景别 |
| `pose_ref` | 可选姿势线稿参考图（动作页用） |
| `nar` / `bubs` / `ch` | 文字层（**只给剪辑应用，不进生图提示词**） |
| `task_id` / `status` / `retry_of` | 生成任务与单格重生成记录 |

**为什么用 JSON 而不是多张表**：页数是 8–24 的固定小集合，需要整体编辑、整包导出、整包人审；JSON 更贴 `panel-spec.json` 对接契约。

## 4. 生图流程编排（六阶段，核心）

### 阶段 A · 立项与角色卡（门控 ①）

1. **选固定角色**。两条来源：
   - `characters` 表 —— 已内置 `reference_image_anime` / `reference_image_realistic` 双字段，`character.service.ts:87` 已有 `style === 'anime' ? anime : realistic` 取图逻辑 → **双风格天然支持，不用加字段**
   - `global_assets` 中 `type='character'` 的人物素材（有 `image_url` / `description` / `prompt`）
2. ⚠️ **实测：当前素材库没有角色** —— `global_assets` 只有 video/audio/scene 各 1 条，`characters` 表为空。所以开工第一步是**录入一个角色**（可先用今天验证过的真人人物照 `D:\AI-Gen-Outputs\agnes-tri\person-real.small.jpg` 做首测）。
3. 生成/填写**角色卡**（固定文本块，全片复用，一次写定不再改）：脸型、发型发色、瞳色、肤色、体型、**服装逐件**、配饰、标志性特征。
4. 选 `style_mode`、`ratio=2:3`、`image_size`（小样 1K / 正式 2K）、模型（2.5 默认）。

### 阶段 B · 剧情 → 分格脚本（门控 ②：人审后才允许生成）

- 用户写一段剧情/大纲（或选题材模板）→ **LLM 一次性输出完整 8–16 格 JSON**，不是逐页让模型自由发挥
- 复用现成通路：`AIServiceUtil.chatCompletion()` + `prompt_templates`（`script.service.ts` 的 `splitWithAI` 已是同款「模板替换 → chatCompletion → 正则抽 JSON → 映射数组」）
- 强制每格输出：`page_no / scene_id / continuity / reuse_group / action / expression / camera / narration / dialogue / choice`
- **强制 LLM 标注 `reuse_group`**：仅表情/台词变化的连续格归为同组（对齐参考作 16 格 → 8~10 张底图）
- 门控：脚本表格可逐格编辑（改动作、改台词、调顺序、合并/拆分复用组、给动作页挂姿势图），**用户点「确认分格」后才进生成**

### 阶段 C · 页级归并（省积分 + 保一致）

按 `reuse_group` 归并出「待生成底图清单」`N` 张（`N ≤ 页数`），每格回填 `base_image_id`。同组格在导出时复制同一张 PNG，仅文字层不同。

### 阶段 D · 逐底图生成（核心执行体）

**每页参考图组（≤ 9 张，现有图生图上限）**：

| 序 | 参考图 | 何时用 |
|---|---|---|
| 1 | 角色参考图（`reference_image_realistic` 或 `_anime`，按 style_mode） | **每页必带** |
| 2 | 服装参考图 | 有独立服装素材时（今天 R7 两参考验证有效） |
| 3 | **姿势线稿参考图** | 仅 `action` 非空且用户挂了 `pose_ref` 的「动作页」（11-05 §11.8 三参考实测成功：举头/叉腰/腿开立/重心侧移都做出来了） |
| 4 | 上一页成图（承接） | **默认关**，可选开启；防累积漂移，见 §10 |

**每页提示词 = 七段固定结构**（前 3 段全片逐字不变，只有第 6 段是变量）：

```
[1] IDENTITY ONLY      —— 角色卡全文：keep her exact face, <发型/发色/瞳色/肤色/体型>.
                           Ignore whatever she wears in the reference.
[2] COSTUME ONLY       —— 服装卡全文：逐件 <上衣/下装/鞋/包/配饰> + 颜色材质.
[3] STYLE              —— 真人：photorealistic photograph of a real person, natural skin
                           texture, soft studio light, full-body/medium shot…
                           动漫：anime illustration, clean line art, cel shading, flat colour…
[4] SCENE ANCHOR       —— 本场景固定：地点 / 时间 / 光线 / 背景，同场景各格一致
[5] CONTINUITY         —— 承接上页一句话（不重复场景描述）
[6] THIS PANEL         —— 本格唯一变量：action / expression / camera / pose_ref 指向
[7] HARD NEGATIVE      —— ONE single finished image of ONE person;
                           NO Chinese text, NO speech bubbles, NO captions,
                           NO collage / triptych / split panels / multiple scenes,
                           NO second figure, NO outfit change, NO mannequin lines.
```

**五条纪律（都是今天/11-05 实测换来的）**：

1. `style: undefined` —— 图生图绝对不要传 `style` 参数，否则 `generateImage()` 会注入 `photorealistic,highly detailed real person,` 之类前缀污染参考图（`runImageToImage` 已这么做）
2. **禁分镜语言** —— 不写「镜头先拍…再展示…最后回切…」，会做成三格拼图（`docs\图生图-提示词指南.md`）
3. **禁中文** —— 所有文字留给剪辑应用排版层
4. **禁长强制块** —— R8 证明把某一项提到超长最高优先级会挤掉鞋/画风；固定块保持紧凑
5. **比例锁 `2:3`** —— 对齐剪辑应用 1024×1536 画布；`AGNES_IMAGE_RATIOS` 已含该比例

**调度**：

- 串行队列逐张跑（Agnes 限流 429 间隔约 200s，偶发 500 重试）
- 直接复用 `runImageToImage()` 已有能力：`prepareReferenceImages()`（本地 `/static/*` → ffmpeg 压缩 → base64）→ `generateImage({ referenceImages, style: undefined, ratio })` → `downloadToLocal()` → 写 `media_files` → 进度/退款
- 建议把其中的执行体抽成 `generateOnePanel()` 公共方法，**不要复制一份生图逻辑**
- 每张一个 `GenerationTask`（`source='comic_panel'`），失败自动退款，**单格可独立重生成**（换姿势图 / 改 THIS PANEL / 换模型）
- 生成页实时显示每格状态与缩略图

### 阶段 E · 导出漫画包

1. 复用格按 `reuse_group` 复制同一底图 → 输出 `格01.png … 格NN.png`（统一缩放到 1024×1536）
2. 写 `panel-spec.json`（§2 格式）+ `manifest.json`
3. 打包 ZIP，提供下载；同时在项目内保留可再次导出

### 阶段 F · 剪辑应用接力（二期，需用户拍板）

`/comic` 增加「导入漫画包」→ 按 `panel-spec.json` 批量套旁白/气泡/分支卡 → 逐格微调 → `POST /api/comic/export` 落 `output/<任务>/comic/格NN.png`。这一端负责**完善剧情**（补台词、分支、节奏、旁白），也是用户说的「用剪辑应用完善整个漫画剧情」。

## 5. 三个目标怎么落地（逐条对应）

| 用户目标 | 工程手段 | 已验证依据 | 验收口径 |
|---|---|---|---|
| **剧情正常链接** | 分格脚本是唯一真相源；LLM **一次性**生成全套起承转合；每格 `continuity` 承接上页；人审门控后才生成 | `script.service.ts` 的 LLM 拆镜通路现成；今天三格拼图事故证明「逐页自由发挥」不可行 | 16 格按序读下来故事连贯、场景/服装状态不矛盾、无重复或跳页 |
| **人物样貌服装一致** | ①**复用底图为主**（同组只生 1 张）②每页必带同一张角色参考图 ③角色卡 + 服装卡逐件固定文本 ④Agnes **无 seed**，明确不靠种子 ⑤双风格各一张参考图 | 参考作逐格比对结论；R7 两参考（真人人物+服装）全套服装正确；11-05 §11.8 换真人参考图后身份漂移消失 | 同角色跨格脸型/发型/服装逐件一致；同 `reuse_group` 100% 像素一致 |
| **某一页的动作能正常做出来** | 动作页单独挂**姿势线稿参考图**（第 3 张），THIS PANEL 写几何锚点；动作页**不参与复用组**；生成后人工确认，不满意单格重生成 | 11-05 §11.8：真人人物 + 服装 + `full_sexy_P001` 线稿三参考 → 举头/叉腰/腿开立/重心侧移全实现，无线稿残留 | 指定页的动作要素逐项达成；不出现三格拼图、不出现摸额头式软化 |

**关于动作的一个诚实边界**：11-03 曾记录「关节线稿 3/3 被 `content_policy_violation` 拦」，11-05 三参考却成功。差异未做单变量对照，官方结论已修正为「**特定组合下会失败，不是绝对**」。所以动作页必须提供**降级路径**：姿势图被拦或效果不对 → 去掉姿势图，改用纯文字几何锚点 + 单格重生成；再不行则该格改用「复用底图 + 排版层表达」。

## 6. 双风格设计

| | `live_action` 真人漫画（先测） | `anime` 动漫漫画 |
|---|---|---|
| 角色参考图 | `characters.reference_image_realistic` | `characters.reference_image_anime` |
| `STYLE` 块 | photorealistic photograph, real person, natural skin texture, soft light | anime illustration, clean line art, cel shading, flat colour |
| 已有取图逻辑 | `character.service.ts:87` 按 style 选字段，**现成** | 同左 |
| 分格脚本 | **共用同一份** `panel_spec` | 同左 |
| 输出 | 两套底图包，可对比 | 同左 |

参考作本身是动漫风，但用户明确**先测真人风格**：真人路线用 `person-real.small.jpg` 这类真人人物照 + 服装图，正好复用今天已验证的素材与结论。同一份剧本可切换风格再出一版，不重复写剧情。

> 参考作「跨格同脸靠复用底图」的结论在真人风格下**更该坚持** —— 真人身份比动漫更容易漂移（今天 R7 用 2D 插画当人物参考时三张脸互不一致，换真人照才解决）。

### 14.1 参考资料与结论

视频《一分钟搞定！锁定角色参考，漫剧主角脸型再也不翻车》（30s，1280×720，作者 小🈚️，2026-11-05）：

- 逐帧（原 6 张 + ffmpeg 每 2 秒补抽 15 张 + 2 张拼图）+ 原声 wav 用 `faster_whisper` 转录（PyAV 版本冲突，改由 ffmpeg 解码成 16k 单声道 float32 数组喂模型绕过）。
- 口播主线（错字已校正）：
  > 「今天要学的是**角色一致性**……你们是不是还在用这样的**角色三视图**来控制人物一致性？……这种三视图不仅**容易卡审**，而且生成的视频里**脸还是会变**……今天教你一种办法……现在用的都是这种**人物角色设定本**……人物的基本信息、脸部特征、人物三视图、不同的脸部表情、服饰配饰全部都要做出来……**有了这张图就能精准控制人物一致性**……skill 和生成工具都整理好了。」

**关键：视频不是简单的三视图教学，而是在说「裸三视图不够」**，要用一张整合的 `CHARACTER PROFILE` 设定本。逐帧可见版式：

| 区块 | 内容 |
|---|---|
| 左 | 超大正面头像（脸部特征）+ 角色名（如「月璃 YUE LI」）+ `3D CHARACTER SHEET` 标识 |
| 中上 | **角色档案**：姓名 / 身高 / 年龄 / 性别 / 职业 / 性格 / 武器 / 外貌描述 |
| 中 | **FRONT / SIDE / BACK 三视图**，全身从头到脚 |
| 中下 | **表情参考**一排 5 个（冷漠 / 微笑 / 害羞 / 委屈 / 生气）+ 细节展示（眼部、唇部、正脸特写）、服装细节 |
| 右竖列 | **三视图细节 DETAILS**：眼部、头部、发饰、肩颈、腰饰、裙摆、鞋类等局部特写 |
| 右下 | 配色色卡 |

另与 `D:/剪辑应用/AI漫剧分镜与提示词模板.md` §3「模板 C 人物一致性（Character Sheet 参考图）」完全一致：多视角全身像、9:16 全景、后续所有镜头把它设为参考图、**服装逐项写清**（跨镜头最易改样）。

### 14.2 V1 的问题（明确认错）

| V1 做法 | 问题 |
|---|---|
| 立项让用户**手填角色卡 / 手选固定角色** | 角色不是从剧情来的；用户还没写故事就得先知道有谁、长什么样、穿什么 |
| LLM 直接一次性输出**分格脚本** | 跳过了「大纲 → 人物识别 → 人设 → 设定本」三道前置工序，人物信息是凭空写的 |
| 每页参考图 = 用户提供的静态角色照片 + 服装图 | 没有**为本项目这个人设专门生成的角色设定本**，模型只能靠文字描述锁脸，身份漂移不可避免 |
| 没有多人物概念 | 剧情里出现第二个人就无从处理 |

**V1 唯一该保留的是「复用组」**：参考作逐格比对证明连续格复用同一底图，这仍是 V2 第三阶段的省图与保一致手段，不冲突。

### 14.3 V2 标准流程（按用户说法）

```
【阶段 1】剧情大纲 → 人物识别
  灵感/题材（一句话）
    → [LLM-1] 生成完整剧情大纲（起承转合、场景、冲突、结局）
    → [门控 1] 人审大纲
    → [LLM-2] 解析大纲，识别出全部人物 Character[]
       每人：姓名 / 身份 / 性别年龄 / 外貌 / 发型发色 / 性格 / 服装逐件 / 标志性配饰 / 出场页
    → [门控 2] 人审人物列表（增删改）

【阶段 2】人设 → 角色设定本（角色一致性的唯一基准）
  每个 Character
    → [LLM-3] 按人设生成「设定本提示词」：脸部特征 + 服装逐件 + 三视图版式
              + 表情参考 + 服饰/发饰局部特写 + 色卡（文字标签另说）
    → [生图] 生成该人物的 CHARACTER PROFILE 设定本（1 人 1 张，可重生成）
    → [门控 3] 人审并**锁定**设定本；锁定后本次项目不再改动
    → 落盘为 `/static/character_sheet_<id>_<char>.png`

【阶段 3】按页剧情，用角色图生成剧情图
  [LLM-4] 分格脚本：每页带 characters[]（出场人物）、continuity、reuse_group、
          action / expression / camera / narration / dialogue / choice
    → [门控 4] 审格 + 用量预估
    → 每页参考图组 = 出场人物的设定本（1~N 张）
                    + 本页姿势参考图（动作页，可选）
                    + 上一页成图（承接，默认关）
                    （总 ≤ 9，沿用图生图上限）
    → [生图] 每页剧情底图（复用组只出 1 张）
    → 导出漫画包（格NN.png + panel-spec.json + manifest.json）
```

三个阶段的产物都是**可人工确认、可单独重生成**的，任何一步不满意都不用推翻全流程。

### 14.4 两个必须写进实现的工程约束

**① 设定本生成不能套用剧情页的负面清单。** V1 的 `HARD NEGATIVE` 明令 `NO collage / NO triptych / NO split panels / NO Chinese text`，而设定本**本来就是多格版式**。设定本必须用独立的提示词模板（显式要求 FRONT/SIDE/BACK + 表情组 + 局部特写 + 色卡的版式），并走独立的生成入口，否则会自我冲突。

**② 设定本里的文字不要交给 Agnes。** 11-05 实测「Agnes 一次渲染十几处中文必崩」（大字号勉强、小字乱码）。两条路线：

- **推荐 B（分块生成 + 后端拼版）**：Agnes 分别生成「正面头像」「三视图」「表情组」「局部特写」等图像块，后端用 ffmpeg/canvas 拼成一张设定本，档案文字、标签、色卡说明由排版层加。版式稳定、中文零风险、单块可重生成。
- 备选 A（一次出整张）：提示词要求整张 CHARACTER PROFILE，接受版式与文字不稳定，仅适合快速试效果。

### 16.1 Bug：设定本「重新生成」会把 4 个块全部重来，已成功的图丢失

**现象**：角色设定本四个块（正面头像 / 三视图 / 表情组 / 局部特写）里，若只有正面头像生成成功、其余三块没生成好，点「重新生成」会 **4 块一起重新生成**，已成功的正面头像也丢失，并重复扣积分。

**根因**（`comic-studio.service.ts` → `generateCharacterSheet()`）：
```ts
c.blocks = [];              // 无条件清空全部块（含已成功的 url / task_id）
c.sheet_url = undefined;    // 已拼好的设定本也一起丢
for (const b of SHEET_BLOCKS) { ...createSheetBlockTask... }   // 无条件重建 4 个任务
```
前端 `genSheet(characterId)` 也只有「生成 / 重生成」一个粒度，没有块级入口。

**影响**：多块生成 + Agnes 限流排队时，只要有一块失败就要全部重来，成本与时间被放大；这正是用户说「模型要排队、一下子出不来」时最痛的点。

**下次修法（建议，不实施）**：
1. `generateCharacterSheet(userId, id, { characterId, blocks?: string[] })` 支持**指定块**重生成；不传时默认只重建 `status !== 'completed'` 的块。
2. 保留其它块的 `url` / `task_id` / `status`，**不清空** `sheet_url`；只在块 url 变化时把设定本标为「需重新拼版」。
3. `assembleSheet()` 幂等：任一块 url 变化即按 4 块当前 url 重新拼版，不要求四块同时新生成。
4. 前端每个块加「重生成此块」按钮与「换用素材图」入口；「全部重生成」需二次确认并提示会重复扣积分。
5. 计费只对新生成的块扣；`status()` 的双路回填逻辑已支持部分块完成，无需大改。
6. 验收：只重生成失败块后，已成功块 url 不变、设定本可重新拼出、积分只增加 1 块。

### 16.2 改良提案：设定本块级来源 = 模型生成 / 现成素材图（**判断：可行，建议采纳**）

**用户想法**：既然装了「人体姿势衣装图库」skill，里面有人脸、服装、姿势可直接应用，就应该直接拿现有图片再加工，不必让模型生成 4 张设定本图，减少生成压力。

**核实结论（重要边界）**：
- skill `pose-costume-character` 的三输入模型是 **人物 / 姿势 / 服饰**；但在线参考库 `catalog.json` 的 `kind` **只有 `pose` 与 `costume`**（如 `P047`、`SPR-0050`，姿势还有 `front/high/low/side/diag` 角度变体），**没有独立的人脸/face 类目**。
- 「人物」基准需来自：用户上传的照片、`global_assets(type=character)`，或 `characters.reference_image_realistic` / `reference_image_anime` 双风格字段。项目里已有验证过的 `person-real.small.jpg`、`costume-SPR-0003.small.jpg`、`pose-fullsexy-P001.small.jpg` 等小图可直接复用。
- 所以准确表述是：**姿势、服饰可直接从库里按编号选；人物基准用已有照片**，三者合起来正好对应 skill 的三输入，也对应项目图生图「1–9 张参考图」能力。

**为什么可行（今天已验证的证据）**：
- 11-05 §11.8：真人人物 + 服装 + 线稿姿势三参考 → 姿势（举头/叉腰/腿开立/重心侧移）全部生效、人物与服装都对，无线稿残留。
- R7 两参考（真人人物 + 服装）→ 全套服装逐件还原；换真人参考图后身份漂移消失。
- 4 张参考图 HTTP 200（49.8s），官方当前体验价下输入参考图不额外收费。
- 参考作逐格比对结论：跨格同脸主要靠复用同一张底图，不靠模型反复生成身份图。
- V2 的 `buildRefs()` 已经是「按出场人物取参考图」结构，块级来源改造不影响第三阶段。

**建议实现（下次）**：
1. `ComicCharacter.blocks[]` 增加 `source: 'generated' | 'library'`、`asset_url`、`locked`；`sheet_mode` 扩展 `hybrid`。
2. 前端设定本页每块可切换来源：
   - `library`：从 `global_assets` 人物/服装/姿势，或输入 skill 参考编号（后端按 `catalog.json` 解析 `original` 图并落到本地 `/static/`）→ **0 次生成**。
   - `generated`：仍按 V2 的 4 块提示词生成（可单块重生成，见 §16.1）。
3. 设定本拼版不变（4 块 2×2），只是块来源不同；档案文字仍只在 DB/JSON，不烧进图。
4. 与 §16.1 合流：**块级锁定 + 块级来源 + 块级重生成** 一次做完，避免两次改同一处。
5. 预期收益：每人物 4 次生成 → **0~2 次**，直接缓解 Agnes 429 排队压力；用户手上有满意素材时一致性反而更好。

**风险与前置**：
- 关节线稿姿势图在 Agnes 真人通道有 `content_policy_violation` 记录（11-03 探针 3/3），11-05 三参考又成功 → **不是绝对可靠**，需保留降级：去掉姿势图 → 文字几何锚点 → 该格复用底图。
- skill 在线库是公网 URL，而项目图生图一期只支持 `/static/` 本地路径与资产库；**一期需先下载到 `backend/output/` 或导入 `global_assets`**，公网 URL 直接输入是二期功能（方案 §11.2）。
