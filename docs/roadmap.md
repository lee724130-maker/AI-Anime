## 二、功能增强（用户体验）

### 🟢 视频生成进度细化
**现状**：进度显示 0%→50%→100% 三步跳，用户不清楚到底在等什么
**改进**：对接 Seedance/通义万相的轮询状态 → 映射为百分比（如 submission→10%, processing→40%-90%, completed→100%）

### 🟢 生成失败原因优化
**现状**：错误信息直接吐后端异常文案（如 `ModelNotOpenError`），用户看不懂
**改进**：中文翻译映射表 + 建议操作（如"模型额度不足，已自动切换到备用模型"）

### 🟢 视频播放器增强
**现状**：简单的 `<video>` + VideoPlayer 组件
**改进**：倍速播放、画中画、清晰度切换（480p/720p/1080p）、进度条缩略图

### 🟢 Studio 用户体验打磨
| 改进 | 说明 |
|------|------|
| 生成中显示预计剩余时间 | 根据队列长度估算 |
| 批量生成进度条 | N 个场景中已完成 M 个 |
| 草稿自动保存 | 角色/剧本选择不因刷新丢失 |

## 三、运维与维护（技术债）

### 🔴 output/ 磁盘清理
**现状**：视频文件一直在 `output/` 累积，无清理策略
**方案**：
- 7 天前的临时文件自动删除（cron job）
- 或迁移到对象存储（阿里云 OSS），URL 持久化到数据库
- 管理后台添加「磁盘使用情况」面板

### 🔴 API 额度监控
**现状**：通义万相/Seedance 有每日免费额度，用完前无预警
**方案**：
- 后端每次调用后解析响应头中的剩余配额
- 存 `system_configs` 实时更新
- 管理后台显示各模型剩余额度
- 低于 20% 时告警（控制台日志 + 后台红色提示）

### 🟡 前端体积优化
**现状**：Vite 提示 chunk > 500KB，antd 全量引入
**方案**：
- `vite.config.ts` 配置 `manualChunks` 分离 antd
- 或改用 `antd/es/` 按需导入

### 🟡 单元测试
**现状**：2 个测试文件，覆盖率接近 0%
**方案**：优先覆盖
- `ai-service.util.ts` — 模型路由逻辑、fallback 链
- `video.processor.ts` — 生成流程状态转移
- `ffmpeg.util.ts` — 视频参数解析

| 问题 | 影响 | 当前处理 |
|------|------|----------|

| 模型额度不可预测 | 免费额度随时可能耗尽 | 9 模型 fallback 链自动降级 ✅ |

## 七、开发流程

### 并行编辑流程（避免 watch mode 卡顿）

`opencode` 编辑文件时会触发 NestJS `start:dev` watcher 重新编译。旧模式串行编辑导致重复重编，新模式如下：

| 步骤 | 旧模式（卡顿） | 新模式（流畅） |
|------|--------------|--------------|
| 读取文件 | 读一个改一个 | 一次消息并行读取所有 |
| 编辑文件 | 串行 edit，每次触发重编 | 一次消息并行发出所有 edit，watcher 只触发 **1 次** |
| npm install | 混在编辑中 | 单独步骤，提前告知用户 |

**注意**：如果编辑时仍出现未响应，说明编辑文件数较多（>10 个），可以暂停等 watcher 完成重编后再继续操作。

**已解决**：此前出现的全局未响应问题，原因是存放会话记录的 `opencode.db` 文件体积过大（会话记录过多导致）。删除 `opencode.db` 文件后恢复正常，不再出现未响应。
