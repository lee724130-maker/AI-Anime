# 前端质感改造规范 · 样板页 `/generate`（2026-11-17）

> 阶段目标：功能问题基本收敛后，把页面做出「更高级更有质感」。约定＝**`/dashboard` 保持不动，其余页面全改**；先只改样板页 `/generate`，方向认可后逐页铺开。
> 本文是后续每个页面都要照做的配方，含令牌表、命名约定、禁止事项与验证口径。

## 一、根因（实测，不是观感推测）

1. **变量名对不上**：页面到处写 `background: 'var(--card)'`，但 `src/index.css` 只定义了 `--card-bg` / `--hover-bg`，`--card` 与 `--hover` **从未定义** → 卡片背景解析为空、整页透明贴底；暗色下 hover 落到兜底浅灰 `#f5f5f5`，跳色刺眼。
   - 探针实测：改造前 `getComputedStyle(documentElement)['--card'] = ''`；改造后 `= #151f2e`。
2. **版式靠内联魔法数字**：`75% / 25%` 两栏、参数行 `Space + flex: '1 1 XXXpx'`、积分规则整块 Alert 常驻 → 层级平、噪音大、控件参差不齐。
3. **没有统一尺度**：字号、间距、圆角、阴影每处各写各的，改一处好看不等于整体好看。

## 二、三层结构（每页都按这个分层）

| 层 | 文件 | 职责 | 硬约束 |
|---|---|---|---|
| 令牌层 | `src/styles/tokens.css`（`main.tsx` 引入） | 只定义 CSS 变量：分层色、影深、发光、间距、圆角、字号、动效、渐变、骨架尺度 | **只写变量、零选择器**；不改 `--card-bg` 等既有值，避免波及未改造页面（含 `/dashboard`） |
| 页作用域样式 | `src/pages/<页面>/<页面>.css`（页面自己 import） | 布局栅格、卡片、控件外观、微交互 | 类名一律带页面前缀（generate 用 `.gen-*`）；覆盖 antd 必须写成 `.gen-xxx .ant-yyy`，**禁止裸写全局 `.ant-*`** |
| 容器重排 | `src/pages/<页面>/index.tsx` | 只换外层容器与类名 | **Form / state / 接口字段 / 提交逻辑零改动**；文案与数据映射另建小函数（如 `MODE_META`、`thumbOf()`） |

## 三、可用令牌（当前值）

- 表面：`--card`（别名，暗 `#151f2e` / 浅 `#fff`）、`--surface-1/2/3`、`--hover`、`--line`、`--line-strong`
- 影深：`--shadow-1`（贴底）、`--shadow-2`（卡片）、`--shadow-3`（浮层/弹窗）
- 反馈：`--ring`（焦点环）、`--glow`（主色发光）
- 渐变：`--grad-brand`（选中态/主按钮）、`--grad-sheen`（卡头微光）、`--grad-stage`（舞台底纹）
- 尺度：`--sp-1..7`（4/8/12/16/24/32/48）、`--r-sm/md/lg/xl`（8/12/16/22）、`--fs-xs..2xl`（11/12/13/15/17/20）
- 动效：`--t-fast .16s`、`--t-base .24s`、`--ease cubic-bezier(.2,.7,.3,1)`
- 骨架：`--rail-w 364px`、`--content-max 1180px`

## 四、样板页 `/generate` 做了什么

- 两栏 `75%/25%` → 栅格 `minmax(0,1fr) + var(--rail-w)`，窄屏（≤1180px）转单列、历史栏落底部
- 下划线 Tab → **分段控件**（选中态渐变 + 发光，未选中提亮一档，暗色不再黑乎乎）
- 积分规则 Alert → **默认折叠的规则条**（`<details>`，左侧图标块暗示可点）
- 参数行 `Space` → **等宽自适应栅格** `repeat(auto-fit, minmax(168px,1fr))`；说明文字 `grid-column: 1/-1` 独占一行
- 提交行 → **卡内吸底操作条**（顶部分隔线，按钮左、模型/文档/预计扣费右）
- 结果区 → 带底纹的**舞台** + 真空态（图标+标题+引导），空态高 320px → **200px**；翻页箭头改 hover 才浮现的圆形幽灵钮
- 历史项 → **真实缩略图**（解析 `task.results`，外链挂了 `onerror` 自动隐藏、露出表情兜底，不出裂图）+ hover 位移 + 选中左侧品牌条
- 浅色模式补层级：页面底给一层冷灰渐变，卡片靠边框 + 双层投影浮起来

## 五、验证口径（每页都要跑）

1. `npm run build`（= `tsc -b && vite build`）**EXIT=0**——JSX 闭合、类型、`noUnusedLocals` 全在这一关。
2. `node tools/probe-generate-ui.cjs [dark|light]`——桩掉全部 `/api`（**零计费、无需登录态**），出截图到 `tools/.probe/`（已 gitignore）并打印实测数字。
   - 前置：vite dev 在跑，**必须用 `http://localhost:5173`**（vite 只听 IPv6 `::1`，`127.0.0.1` 连不上）。
3. **判好坏靠数字，不靠眼睛**：本轮样板基线＝`--card=#151f2e`、`--hover=rgba(255,255,255,.05)`、`railW=364`、空态 `stageH=200`、参数栅格 `4×188.5px` 等宽、`formItems=38`、`pageErrors=0`。
   - 教训：第一轮视觉复查说「参数栅格宽度参差」，实测 `194.5px×4` 完全等宽——**视觉模型会误判，量出来才算数**。

### antd 排版组件（Text / Title / Paragraph）换类时必须提权（11-24 批次F 实测教训）

把内联 `style={{ color: '#fff' }}` 换成 `className="xxx"` 时，如果该元素是 antd 排版组件，
antd 自己的 `.ant-typography { color: … }` 与页面类**同特异性**，谁后加载谁胜 ——
于是文字色会被 antd 主题色接管。**暗色下常常看着没问题（因为主题文字色恰好接近白），
切到浅色才发现是深字压深底。**

正确写法：用父类 + `.ant-typography` 提权。

```css
.ed-tl__block .ant-typography { color: var(--ed-block-ink); }        /* 固定白，两主题都成立 */
.ed-tl__block .ed-tl__block-sub { color: color-mix(in srgb, var(--ed-block-ink) 75%, transparent); }
```

同理，**「两主题都必须固定」的颜色**要单独声明成页内局部变量并写明原因，不要误用主题令牌：
剪辑器预览舞台（`--ed-stage: #111`）、彩色片段块上的白字（`--ed-block-ink: #fff`）、
音频语义色（`--ed-audio: #0ea5e9`）、Landing 的深色 Hero 品牌带。
反过来，**用户内容数据里的颜色**（文字叠加默认色、颜色选择器回退值、轨道 `TRACK_META.color`）
不属于样式层，一律不动。

### 无 DB 内容页面（营销页）的验证方法：锚点计算样式全量 diff

营销/落地页没有数据库内容，真实数据走查不适用（且表单会写库，绝不能提交）。改用**改造前后逐项比对计算样式**：

1. **锚点按文本定位，不按类名** —— 因为改造会把类名换掉，只有文本定位能让前后两轮命中同一元素。
   需要 `byExact`（`textContent.trim() === t`）与 `byText`（包含）两种：只有精确匹配才不会被
   「输入故事」误命中「输入故事大纲」。
2. **每个锚点读全量属性**（色、底、渐变、阴影、圆角、字号、行高、内距、外距、gap），
   不要只读颜色 —— 令牌化时最容易把 `--fs-md`(13px) 当成原来的 14px、把 `--sp-6`(32px) 当成原来的 24px。
3. **用 `git stash push -- <路径>` / `stash pop` 切换代码状态**，vite 源码热更新即时生效，无需重新构建。
4. **交互态要单独一轮 `evaluate`**：React 状态更新是异步的，点击后必须 `waitForTimeout` 再读，
   不能在同一个 `evaluate` 里点完立刻读。
5. **再补一份逐区块高度指纹**（顶层块 top/height + padding），用来解释「整页高度差了多少」。
6. 结果分类：每项差异必须能归因到「有意变更」（令牌化、色带、hover 改 CSS）或「已修回归」；
   出现无法解释的项就继续下钻到元素级，直到定位为止。

### 缩略图裂图兜底的正确写法（11-24 批次D 定稿）

只写 `onError={(e) => (e.target.src = 备用地址)}` 是**不够的**：备用地址也失败时，浏览器会露出裂图图标 + alt 文字
（`/studio` 的 `probe-ui` 首次报 `brokenImgs=1` 抓到的就是这个，`/video` 列表同一处写法）。正确做法是两级兜底：

```tsx
onError={(e) => {
  const el = e.target as HTMLImageElement;
  if (el.dataset.fallback === '1') { el.style.visibility = 'hidden'; return; }  // 第二级：藏掉
  el.dataset.fallback = '1';
  el.src = 备用地址;                                                            // 第一级：换源
}}
```

`<video>` 同理，`onError` 里直接 `visibility:hidden`。

### 裂图兜底要区分两种组件，且必须能证明「兜底真的触发」（11-25 批次I 补充）

`/viral/templates/:id` 实测有 6 张裂图。根因不在前端：后端把 `viral_templates.cover_url` 填成
`/static/viral_frames_1786097336124/seg_*.jpg`，而这些帧目录**磁盘上不存在**（本地 `output/` 是生产逐字节镜像，
所以生产同样缺）。

两种组件的行为差别是关键：

| 组件 | 有没有兜底 | 结果 |
|---|---|---|
| `CoverThumb`（自带 `onError → setFailed` 走渐变占位分支） | 有 | 列表页 `brokenImgs=0`，**已经兜住** |
| antd `Image`（`preview={false}`，无 `fallback`） | 没有 | 详情页一排浏览器裂图图标 + alt 文字 |

修法（不新增任何静态资源）：`onError` 里把 `<img>` 设为 `visibility:hidden`，同时给容器打
`data-broken="1"`，由 CSS `::after` 出「无截图」文字占位；容器再加 `min-height` 防止栅格塌成 0 高。

**验证口径的教训**（这三条都会造成"假绿"或"假红"）：

1. `visibility:hidden` **保留布局**（`offsetWidth` 仍 > 0）。用 `offsetWidth>0` 判裂图会把已经兜住的图
   继续算成失败 → 假红。必须与 `probe-ui.cjs` 的官方口径一致：
   `complete && naturalWidth===0 && offsetParent!==null && visibility!=='hidden' && display!=='none'`。
2. 只报 `broken=0` 分不清「兜底生效」和「页面根本没图」→ 要**额外统计被藏掉的张数**并对该路由硬断言 `>0`，
   这才真正证明 `onError` 触发过。
3. 两类网络噪音必须排除，否则每次都是红：`net::ERR_ABORTED`（视频元素卸载时浏览器取消 range 请求，正常行为）、
   `favicon.svg` 缺失、以及既有的 `useForm is not connected` 告警（loading 期间 Form 未挂载就用实例）。

另外两条与探针本身有关的坑（同日再犯/复现）：
`querySelector(r.root.slice(1))` 把类名的点号削掉 → 全路由假报 `root=false`；
以及批次H 那条 **`addInitScript` 每次导航都会执行**，主题必须作为参数传进去，否则第二个主题静默失效。
