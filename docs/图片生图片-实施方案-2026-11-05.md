## 二、两个必须先解决的技术约束

### 2.1 【最关键】本地 `/static/` URL 不能直接喂给 Agnes

- 项目上传接口返回 `/api/media/upload` → `{ id, url: '/static/xxx.jpg' }`；大资产库 `global_assets.image_url` 实测也是 `/static/...`。
- Agnes 官方文档：**图生图的 `extra_body.image` 只接受「公网可访问 HTTPS URL」或「Data URI Base64」**，相对路径会直接失败。
- 今天本地脚本成功的做法：用 ffmpeg 把每张参考图压到 640px / 26–43KB，转 `data:image/jpeg;base64,...` 再提交（见 `三参考生图测试-2026-11-05.md`）。
- **结论**：后端必须加一步 `prepareReferenceImages()`：
  1. `/static/xxx` → `resolveSafeStaticPath()` 得本地绝对路径（拒绝 `..` 穿越）
  2. 公网 URL → `assertSafeRemoteUrl()` 校验后下载到临时文件
  3. 统一用 ffmpeg 压到 ≤1024px / ~100KB 的 JPEG
  4. 转 `data:image/jpeg;base64,...` 数组
  - 这样既满足 Agnes，又避免 SSRF 与超大请求体，还绕开"Agnes 端访问不到本地静态资源"的问题。

### 2.2 不要让 `style` 注入污染图生图提示词

`generateImage()` 里 `style==='realistic'` 会强行加 `photorealistic,highly detailed real person,` 前缀，`anime` 会加 `anime style,动漫风格,...`。图生图的画风应由**参考图**决定，硬加前缀会破坏今天 R7/A 组验证过的效果。
→ **调用时传 `style: undefined`**，并且图生图表单**不提供风格下拉**。同理，不复用 `runTextToImage`（它有"prompt 短于 15 字自动 LLM 扩写"和"多视角拆分"逻辑），要写独立的 `runImageToImage`。

### 2.3 官方图生图参数要点（已核实）

- `model` / `prompt` / `size` 必填；`size` 用 `1K~4K` 档位 + `ratio`
- `extra_body.image` 为图片数组（Data URI 或公网 URL）；`response_format` 必须放在 `extra_body` 内
- **不要**传 `tags: ["img2img"]`
- **计费**：刊例价「前 3 张参考图不额外收费，第 4 张起 $0.003/张」；但官方定价页「图片当前计费规则」明确 **当前所有输出档位与输入参考图（含第 4 张及之后）均为 $0**。即 3 张是刊例价的免费额度，**不是张数上限，也不是当前体验价下的免费门槛**（详见 §11.1）
- 支持的 `ratio` 共 8 种：`1:1`、`3:4`、`4:3`、`16:9`、`9:16`、`2:3`、`3:2`、`21:9`（官方默认 `1:1`，本项目默认 `3:4`）
- 官方 API 参数表中 `image: string[]` **未写张数硬上限**
- 文生图请求**不要**带 `image` 字段 → 代码需按 `referenceImages?.length` 条件添加

## 四、完整工作流程（端到端）

```
【前端 /generate → 🖼 图片生图片】
  ① 选参考图来源：大资产库（global_assets）或本地上传（/api/media/upload → /static/xxx）
     → 得到有序 url 数组（1~9 张，顺序即"第1/2/…张"，UI 建议 1~3 张）
  ② 填提示词（可点"智能反推"调 /api/generate/smart-describe 生成初稿）
  ③ 选模型(2.5/2.1)、强度(1K~4K)、比例
  ④ 点提交 → doGenerate('POST /api/generate/image-to-image', payload, form)
        payload = { images: string[], prompt, model, image_size, ratio }
                    ↓
【后端 Controller】
  @Post('image-to-image')  imageToImage(@Req req, @Body body)
    → GenerateService.imageToImage(req.user.id, body)
                    ↓
【GenerateService.imageToImage】
  ⑤ 校验：images 1~9 张非空（上限常量 I2I_MAX_IMAGES=9）；model ∈ AGNES_IMAGE_MODELS；
          image_size ∈ 1K~4K；ratio ∈ 官方 8 种白名单
  ⑥ 计费 estimateCreditCost({type:'image', num_images:1, image_size}) → creditsService.charge（不足则 400）
  ⑦ 建任务：type='image', source='image_to_image', status='processing',
            model_name=实际模型, credit_cost, input_data=JSON(dto)  ← 存参考图 url 便于重试/追溯
  ⑧ enqueue(() => runImageToImage(...)) ；立即返回 { taskId, status:'processing' }
                    ↓
【GenerateService.runImageToImage（后台）】
  ⑨ prepareReferenceImages(dto.images)：
       /static/* → resolveSafeStaticPath → 本地文件
       公网 URL  → assertSafeRemoteUrl → 下载临时文件
       统一 ffmpeg 压到 ≤1024px/~100KB JPEG → data:image/jpeg;base64,...
  ⑩ aiService.generateImage({
        prompt, model, numImages:1, width, height, imageSize, ratio?,
        referenceImages: dataURI[],
        style: undefined          ← 关键：不注入画风前缀
      })
                    ↓
【AIServiceUtil.generateImage】
  ⑪ provider='agnes'（已统一）→ 白名单校验 → generateImageWithAgnes(agnes_api_key, options)
        （不走 LLM 扩写、不走多视角拆分、不走其他厂商）
                    ↓
【generateImageWithAgnes】
  ⑫ POST https://api.agnes-ai.cn/v1/images/generations
      body = { model, prompt, size, ratio, n:1,
               extra_body: { response_format:'url',
                             ...(referenceImages?.length ? { image: referenceImages } : {}) } }
      → data[0].url
                    ↓
【结果落盘】
  ⑬ downloadToLocal(url, `i2i_${taskId}`) → /static/xxx.png
  ⑭ mediaRepo.save({ user_id, task_id, type:'image', url, mime_type:'image/png' })
  ⑮ task.output_data = JSON.stringify([{ id, url, view:'结果' }])   ← 与文生图同格式
     task.status='completed' / progress 100 / finalizeTask
  ⑯ 任意环节失败 → status='failed'、error_msg、creditsService.refund（未扣标记时）、finalizeTask
     内容审核拦截（线稿类参考图）转成友好提示；429 限流按现有策略处理
                    ↓
【前端】
  ⑰ fetchHistory() → 历史轮播按 output_data 数组展开显示成图
```

{ "model": "agnes-image-2.5-flash", "prompt": "…",

## 七、错误处理与风险

| 风险 | 处理 |
|---|---|
| 参考图为空 / >3 张 | 400 明确提示 |
| `/static/` 路径含 `..` 穿越 | `resolveSafeStaticPath` 返回 null → 400，不读文件 |
| 公网 URL SSRF | `assertSafeRemoteUrl` 校验（一期可不开放公网 URL 输入） |
| 请求体过大 / 超时 | ffmpeg 压到 ≤1024px/~100KB 再 base64；客户端 timeout 沿用 120s |
| **关节人偶线稿类参考图触发 `content_policy_violation`** | 今日实测：特定组合会被拦；`generateImageWithAgnes` 已有敏感词识别，转友好提示；UI 加一句「人体线稿类参考图可能被内容审核拦截」 |
| 429 限流 | 沿用现有未实名 key 退避；页面提示「服务繁忙请稍后重试」 |
| 生成失败 | 退款 + `error_msg`，与文生图一致 |
| 姿势不按参考图 | 今日 R4/R5 结论：i2i 下姿势受参考图先验影响；本方案提供自由提示词与「高级提示词」由用户控制，不承诺姿势 100% 还原 |

## 十一、17:59 官方核实与决策确认（覆盖前述「建议」）

### 11.1 参考图到底能传几张、会不会扣费 —— 你问对了，我之前措辞不准

查官方 `https://www.agnes-ai.com/zh-Hans/docs/pricing`「图片模型」与「图片当前计费规则」，原文：

> 刊例价费用 = 输出图片张数 × 对应输出分辨率单价 + max(0, 输入图片张数 - 3) × $0.003
> **当前价格为 `$0`：所有支持分辨率档位的输出图片均免费，输入参考图片（包括第 4 张及之后）也不收费。**

| 概念 | 实际含义 |
|---|---|
| 「前 3 张免费」 | **刊例价**下的免费额度，不是张数上限，也不是当前体验价的门槛 |
| 第 4 张起 | 刊例价 `$0.003/张`，**体验价 `$0/张`** → 现在不扣费 |
| 一次请求最多几张 | 官方 API 参数 `image: string[]` **未写硬上限**；计费公式本身允许超过 3 张 |
| 2.0 / 2.1 / 2.5 | 三者价格与计费方法相同，规则一致 |

**结论：3 张不是「免费上限」，超过 3 张当前同样不扣费 → 按你的要求把上限拉高。**

- 最终设定：**1–9 张**（`I2I_MAX_IMAGES = 9`），与前端现成的 `MAX_LIBRARY_ASSETS = 9` 对齐，零额外改动
- 已启动 4 张参考图实测（`verify-4images.cjs`）确认服务端接受 >3 张，结果记录在 §11.5
- UI 保留软提示「建议 1–3 张；张数越多请求体越大、耗时越长」，不硬拦
- ⚠️ 体验价只适用于官方 `default` 试用用户；**Agent Plan 用户按刊例价、不享体验价**。项目当前是未实名 default key，属前者。将来若换账户类型，超过 3 张会真扣 `$0.003/张`，届时需重新评估上限与提示文案。
- 平台内部积分仍是 5 分 × 档位倍数 × 1 张，与参考图张数无关（平台侧不额外收）

**真正的约束不是钱，是工程**：base64 会让每张图膨胀约 33%，9 张未压缩原图可能让请求体达到几十 MB 并触发超时/限流。所以 `prepareReferenceImages()` 的压缩（≤1024px / ~100KB JPEG）是必须的，且超过 6 张时建议在后端再做一次总大小校验。

### 11.2 一期不做、二期必做：公网 URL 输入的**具体作用**

你特别想测这个，说明白它是干什么的：

**定义**：用户直接粘贴一个**公网可访问的 HTTPS 图片链接**当参考图，不必先把图片下载到本机、再上传到项目。它是「大资产库 / 本地上传」之外的**第三种参考图来源**。

**具体能做什么（按与你现有工作流的相关度排）**：

1. **直接吃在线参考库的图** ⭐ 最贴你现在的活。你在 `hongye007.github.io/open-pose-costume`（omilic.com）挑的姿势图、服饰图、人物图都是公网 URL；今天三参考实验里我是先把它们下载到本地再压缩上传。二期做了之后，**复制图片地址 → 粘贴 → 直接生成**，中间三步全省。今天验证成功的「人物+姿势+服饰」融合就能在页面上一次跑通。
2. **跨平台 / 别人的素材**：CDN 上的电商商品图、图床、素材站预览图、同事发的图片链接，不用先存到本地。
3. **不占本地存储**：参考图不落 `media_files`，不吃用户 500MB 配额，也不产生一堆"一次性上传"的垃圾文件。
4. **快速 A/B**：换一个 URL 就换一张参考图，比反复上传快得多；适合比对不同姿势/服饰编号的效果。
5. **自动化 / 外部系统对接**：脚本、导出桥、AI-Anime 的 `drama_assets`（若存外链）可以直接把 URL 传给 API，不需要先走上传接口。这是产品化时最关键的一条——机器调 API 时手里往往只有 URL。
6. **测「链接可用性」边界**：防盗链、需要 cookie、临时签名 URL、大图、非图片 MIME 等失败场景，二期都要给清晰报错。

**二期实现要点**（不进一期，但架构要留口）：
- 前端：`assetSource` 增加第三个选项 `url`，提供多行 URL 输入 + 缩略图预览 + 添加/删除，与前两种来源并列
- 后端：`prepareReferenceImages()` 已经规划了「公网 URL → `assertSafeRemoteUrl()` 校验 → 下载临时文件」这条分支，**二期只需放开入口校验**，不需要重写转换逻辑
- 安全：必须校验 HTTPS、拒绝内网/回环/元数据地址（防 SSRF）、限制下载大小与超时、限制重定向
- 稳定性：即使 Agnes 官方支持直接传 URL，也建议**后端下载后统一转 base64** 再提交——避免 Agnes 端访问不到、防盗链、链接过期等问题，同时复用同一套压缩逻辑
- 官方要求原文：「请使用公共 HTTPS 图像 URL，并确认不需要登录、cookie 或私有请求头；如果无法公开访问，请使用 Data URI Base64」

### 11.3 为什么建议「独立状态」——详细解释

**现状：三个 `useState` 是页面级单例，被所有 tab 共享**

```ts
const [assetSource, setAssetSource] = useState<'upload'|'library'>('library');
const [uploadFileList, setUploadFileList] = useState<any[]>([]);
const [selectedLibraryAssets, setSelectedLibraryAssets] = useState<any[]>([]);
const MAX_LIBRARY_ASSETS = 9;
```

而且耦合比看上去更深：

- `uploadProps.onChange` / `onRemove` 里**写死了** `formImageToVideo.setFieldsValue({ image_url, media })` —— 上传组件天生只服务图生视频表单
- `doGenerate()` 提交成功后无条件 `setUploadFileList([])` + `setSelectedLibraryAssets([])`
- 图生视频表单的 `Radio.Group value={assetSource}` 直接绑这个共享值

**如果图生图片直接复用，会出现的真实故障**：

| # | 场景 | 后果 |
|---|---|---|
| 1 | 在「图片生视频」选了 3 张 → 切到「图片生图片」 | 看到同样的 3 张，用户以为是自己选的（**串图**） |
| 2 | 在图生图片选了新图 → 切回图片生视频 | 它的 `image_url` / `media` 隐藏字段和图库显示都变了，提交可能生成错误内容 |
| 3 | 图生图片上传一张图 | `onChange` 往 `formImageToVideo` 写值，**污染了视频表单** |
| 4 | 任一 tab 提交成功 | `doGenerate` 清空共享列表，**另一个 tab 选好的图全没了** |
| 5 | 两个 tab 都有 `Radio.Group value={assetSource}` | 切一个，另一个的选中状态跟着跳 |
| 6 | 图生图片想限 9 张、视频想保持 9 张但语义不同 | 共用 `MAX_LIBRARY_ASSETS`，改一处影响两处 |
| 7 | 以后给图生图片加「拖拽排序」 | 会意外改变视频页的多图顺序，典型的"改 A 坏 B" |

**独立状态 = 给图生图片一套自己的 `i2iAssetSource` / `i2iUploadFileList` / `i2iSelectedAssets` + 自己的 `formImageToImage`**，好处：

1. **彻底隔离**：切 tab 不串图；切回来之前选的还在（体验更好）；提交后只清自己的列表
2. **表单一一对应**：每个 tab 有自己的 `Form.useForm()` 实例，上传回调写到自己表单，不污染别人
3. **各自可定制**：图生图片可以有自己的张数上限、排序、压缩策略、字段映射（`images`），视频保留 `image_url`/`media`/r2v 逻辑
4. **零回归风险** ⭐ 最关键：现有 3 个 tab 一行不用改，测试面只在新 tab；共享方案则必须回归所有 tab
5. **可维护 / 可扩展**：以后加第 5 个 tab 或抽公共组件时，独立状态边界清晰；共享状态会变成没人敢动的隐式契约
6. **调试简单**：出问题只看一个 tab 的状态，不用排查"谁改了共享变量"

**代价**：约 30–40 行重复的上传配置代码 → 用 `makeUploadProps(form, setList, ...)` 工厂函数消除，不是问题。

**备选方案（本次不采用）**：抽公共 `<ImageSourcePicker>` 组件最 DRY，但要重构 `image-to-video` 表单、改变它的字段绑定，回归面大；一期先把新功能做稳，等二期加公网 URL 时再顺手抽组件更合适。

### 11.4 比例：官方 8 种全放，默认 3:4

官方 `agnes-image-2.5-flash` / `2.1-flash` 支持并**仅支持**这 8 种 `ratio`，全部加入下拉：

| ratio | 1K 输出像素 | 2K | 3K | 4K |
|---|---|---|---|---|
| `1:1` | 1024×1024 | 2048² | 3072² | 4096² |
| **`3:4`（默认）** | **864×1152** | 1728×2304 | 2592×3456 | 3456×4608 |
| `4:3` | 1152×864 | 2304×1728 | 3456×2592 | 4608×3456 |
| `16:9` | 1312×736 | 2624×1472 | 3936×2208 | 5248×2944 |
| `9:16` | 736×1312 | 1472×2624 | 2208×3936 | 2944×5248 |
| `2:3` | 832×1248 | 1664×2496 | 2496×3744 | 3328×4992 |
| `3:2` | 1248×832 | 2496×1664 | 3744×2496 | 4992×3328 |
| `21:9` | 1568×672 | 3136×1344 | 4704×2016 | 6272×2688 |

- 官方默认 `1:1`，本项目默认 `3:4`（今日实测人像效果稳）
- 后端做白名单校验，非这 8 种直接 400；不要在前端偷偷改比例
- 「多比例生成图片」：一次提交仍是 1 张图；要出多种比例就分别选、分别提交（保持任务与计费模型简单）。若以后要「一次出 N 个比例」，那是另一个需求，需改任务批处理和计费，本次不做。

### 11.5 5 项最终决策汇总

| # | 决策 | 结论 |
|---|---|---|
| 1 | 参考图上限 | **1–9 张**（当前体验价第 4 张起也 $0；官方无张数硬上限）；UI 软提示建议 1–3 张；4 张实测见下方 |
